------------------------------------------------------------
1. PURPOSE
------------------------------------------------------------

This document defines the economic and commercial model of the BinaryBot
signal ecosystem.

It explains:

• how signals generate revenue
• how users access the ecosystem
• how service tiers are monetized
• how affiliate partners participate in growth
• how commercial packaging must remain aligned with canonical technical architecture

This document does NOT redefine trading logic, signal quality, FSM progression,
or channel routing mechanics.

Those are defined canonically in:

• SIGNAL_DISTRIBUTION_SPEC.md
• CHANNEL_CONFIG_SPEC.md
• TELEGRAM_UX.md
• FSM_SPEC.md
• DECISION_AUDIT_SPEC.md

------------------------------------------------------------
2. CANONICAL RULE
------------------------------------------------------------

The canonical service tier model is:

• FREE
• BASIC
• PRO
• ELITE

No alternative commercial naming system may override or conflict with the
canonical tier model in technical or operational documentation.

Deprecated names that must not be used as canonical runtime tiers:

• STANDARD
• VIP

If legacy commercial language is referenced in old notes or historical drafts,
it must be interpreted as non-canonical.

Canonical mapping going forward:

• STANDARD -> BASIC
• VIP -> ELITE

------------------------------------------------------------
3. SIGNAL PRODUCTION
------------------------------------------------------------

Signals are generated by the BinaryBot engine.

Pipeline:

Market Data
↓
Strategy Engine
↓
Signal Decision FSM
↓
Observability + Audit
↓
Distribution System

Canonical signal stages:

PRE
CONFIRM
OPEN_NOW
RESULT / OUTCOME (where applicable)

The trading engine determines signal quality.

Signal quality is universal and does not vary by commercial tier.

This is a hard rule.

------------------------------------------------------------
4. COMMERCIAL MODEL VS TECHNICAL MODEL
------------------------------------------------------------

Commercial packaging must not redefine strategy quality.

The following distinction is mandatory:

A) Strategy Quality Layer
Defined by:
• market data
• strategy logic
• scoring
• risk gates
• focus policy
• execution timing

B) Distribution / Access Layer
Defined by:
• which channel the user belongs to
• tier limits
• silent mode
• feedback features
• analytics / support / premium tooling

Therefore:

• tiers may differ in access, limits, tooling, reporting, or support
• tiers must NOT imply a different internal quality standard of the strategy

------------------------------------------------------------
6. SIGNAL ACCESS RULE
------------------------------------------------------------

Canonical distribution behavior is NOT stage-segmented by commercial naming.

The canonical rule is:

• if a tier is ACTIVE, it receives PRE / CONFIRM / OPEN_NOW
• if a tier is SILENT, it receives nothing
• ELITE does not become SILENT

This economic document must not redefine that behavior.

Signal stage routing remains governed only by:

• SIGNAL_DISTRIBUTION_SPEC.md
• CHANNEL_CONFIG_SPEC.md

Commercial differences are expressed through:

• tier limits
• support level
• affiliate packaging
• analytics features
• private feedback tools
• premium reporting

------------------------------------------------------------
7. REVENUE MODEL
------------------------------------------------------------

Revenue may be generated through:

• subscription fees
• premium service access
• private analytics / premium reporting
• affiliate distribution networks
• future upsell products

Illustrative example only:

FREE
Price: 0

BASIC
Price: low entry subscription

PRO
Price: mid-tier subscription

ELITE
Price: premium subscription

Exact pricing is a business decision and may evolve without changing
the canonical technical tier names.

------------------------------------------------------------
8. TIER DIFFERENTIATION (ALLOWED)
------------------------------------------------------------

The following tier differences are allowed:

• daily OPEN_NOW capacity
• premium reporting access
• elite-only outcome feedback tools
• private member statistics
• community / education / concierge layers
• affiliate bundles or reseller programs

The following are NOT allowed:

• different strategy formulas per tier
• different quality standards per tier
• fake degradation of signal quality for lower tiers
• alternative runtime tier naming in canonical docs

------------------------------------------------------------
9. ELITE SPECIAL LAYER
------------------------------------------------------------

ELITE may include additional premium features such as:

• outcome reporting
• private personal statistics
• advanced analytics access
• elite-only reporting workflows
• private execution feedback tools

This is consistent with canonical distribution documents and does not
change signal quality.
